# Cyber Security 2.0 — Stage70 V75 PID Recovery — R5 Compose Baseline PID Reconciliation

**Статус: BLOCKED/NO-GO. DAY-04 NOT_RUN. Stage71 NOT_OPENED.**

## Причина исправления

Реальный R4 SSH READONLY Compose diff от 2026-11-26 19:47:49 UTC подтвердил для обоих вариантов A=256, B=384 ровно два отличия: существующее `services.zap.pids_limit` заменяется на экспериментальный конечный бюджет, а отсутствующий `services.zap.shm_size` становится 268435456 байт. Другие различия не выявлены. Предыдущий V75 `compose_pid_delta()` ошибочно отвергал уже существующий pids_limit и неверно нормализовал сравнение `before` и `after`.

## Содержание и преемственность

* Исходный R4 ZIP **побайтово неизменён**, SHA-256 `1c4d9441739ba962b73c7bd72c31aa9f2b41ffe48c578e959cd1d3d5c259aa9c`, включает точный R3 `7956839ac3dcb6800231e4dc3176947d7c972c43aea8e5c851a5a7089a7901c1`, который включает точный исходный V75 и V74 и историческую цепочку.
* Оригинал `EVIDENCE(20261126-194847).zip` SHA-256 `750e5a131f64173de5145a26509f6d882b2e47dedaf98a6d184ea3f1ac71ad7c`; оригинальный журнал Terminal также сохранён.
* R5 при запуске проверяет все эти SHA, безопасно извлекает временную копию R3, применяет проверенный R3 root-fix и **только затем** узкий патч R5 к `pid_recovery.py` и связанным тестам. Файловые манифесты в рабочей копии пересчитываются и проверяются. ZIP-оригиналы не изменяются.
* Изменяются **исключительно** `services.zap.pids_limit` и `services.zap.shm_size`. Требуются исходный finite pids_limit строго положительного целого типа (или канонической десятичной строки) при его наличии, выбранный бюджет 64..512, и shm строго 268435456. Полное сравнение `before`/`after` после удаления *только этих двух полей* запрещает изменения image, mounts, network, UID, caps, `security_opt`, seccomp, NoNewPrivs, target и любых иных полей. Дополнительно обязательна runtime Docker inspect проверка PID и shm.
* Не запускается active scan, публичный target или отключение sandbox. Реальный A/B разрешён исключительно в принадлежащей оператору изолированной UTM Ubuntu ARM64 VM с подтверждённым snapshot, consent, live SSH host key, бюджетами и ручным `YES`. Межпрогонная quiescence обязательна. При ошибке FAIL-CLOSED.
* Тесты исходного V75 адаптированы к доказанному факту существующего конечного лимита; добавлены негативные тесты неканонических, unlimited, bool, отрицательных, сетевых, UID, seccomp и других запрещённых изменений.

## Запуск (macOS, после проверки ZIP SHA-256)

```bash
cd "$HOME/Downloads/Stage70_V75_Compose_Baseline_PID_Fix_R5_LT10MB"
bash Run_Stage70_V75_PID_Recovery_R5.command --mode review
bash Run_Stage70_V75_PID_Recovery_R5.command
```

При двойном клике `.command` открывается интерактивный режим; сначала локальный review. Для `apply` оператор вводит A и B в соответствии с текущим headroom, затем LAB, SNAPSHOT и отдельное YES. Автоматический fallback для отсутствующих PID-метрик запрещён. Ранее выбранные 256 и 384 — только экспериментальные варианты, не рекомендованные для production.

Подтверждён только внешний пользовательский R4 READONLY diff, локальная проверка целостности и результаты регрессионных тестов, приложенные к пакету. **Никакой новый Ubuntu A/B / WebDriver / AJAX Spider / 2-й Passive Scan в этой среде не выполнялся.** Три строгие локальные регрессии не заменяют реальный E2E; при отсутствии всех подтверждений Production остаётся BLOCKED/NO-GO.
